## CI automático (testes em cada commit)

**Problema**: já existem `pytest` e testes E2E (`tests/test_mt5.py`), mas
sem confirmação de que correm automaticamente em cada commit. Com vários
itens desta spec a mexer no mesmo código, possivelmente em paralelo, um CI
apanha regressões antes de chegarem à VPS.

**Objetivo**: configurar GitHub Actions (ou equivalente) para correr
`pytest -q` em cada push/PR, com o resultado visível antes de qualquer
merge para a branch principal.

**Critério de aceitação**: workflow de CI a correr com sucesso no repositório
e a falhar deliberadamente (introduzir um teste que falha de propósito,
temporário) para confirmar que bloqueia/assinala corretamente.
