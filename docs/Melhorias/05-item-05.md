## Recalibração periódica automatizada do `trail_factor`

**Problema**: `trail_factor=2.0` foi calibrado num sweep pontual (19/08). O
grupo já mudou de formato de sinal 3 vezes no histórico — não há garantia de
que o plateau monotónico continue válido para sempre.

**Objetivo**: criar um script/tarefa agendada (mensal, ou disparada quando o
classificador detetar um novo formato de sinal) que corre o sweep de
`trail_factor` (1.5–2.5, mesma grelha do estudo original) sobre os últimos
90 dias de sinais reais, e:
- se o plateau monotónico se mantiver e o meio continuar perto de 2.0, não
  faz nada (só regista o resultado no log de recalibração);
- se o plateau se deslocar de forma consistente (não um pico isolado), abre
  uma notificação no feed/Telegram a propor o novo valor, mas **não aplica
  automaticamente** — decisão fica para revisão humana, como manda a regra
  de nunca automatizar mudanças de parâmetros de risco sem supervisão.

**Critério de aceitação**:
- Script correntemente idempotente, sem look-ahead (só usa sinais já
  resolvidos até à data da corrida).
- Log/tabela de histórico de recalibrações (nunca apagar, à semelhança do
  `fase3_verdicts`).
- Notificação de proposta de mudança testada manualmente pelo menos uma vez
  (simular um deslocamento de plateau e confirmar que a notificação dispara).
