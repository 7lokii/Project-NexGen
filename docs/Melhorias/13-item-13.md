## Usos consultivos do LLM (classificação/deteção/relatório, nunca decisão)

**Contexto**: o LLM já existe no projeto como fallback opcional de parsing de
sinais (`SIGNALBOT_LLM_*`, desligado por defeito), sempre com sanity checks
do regex por cima. Este item estende o mesmo princípio — o LLM ajuda a ver,
explicar ou sinalizar, nunca decide sozinho algo que mexe em dinheiro — a
mais quatro papéis consultivos/assíncronos:

1. **Fallback na classificação de mensagens de gestão**
   (`app/messages/manage.py`): quando o regex/keywords não reconhecer uma
   frase nova do grupo (`protect`/`close_all`/`move_sl`/etc.), o LLM propõe
   uma classificação, mas em vez de agir sozinho na trade, regista a
   proposta e alerta no feed para confirmação — mesmo tratamento do fallback
   de parsing de sinais.
2. **Deteção de mudança de formato do grupo**: corrida periódica (ex.:
   diária) sobre os sinais `failed` recentes; se o LLM identificar um padrão
   recorrente de "isto parece um sinal mas nenhum regex bate", dispara um
   alerta proativo de possível mudança de formato — antes de se perderem
   sinais válidos em massa, como já aconteceu 3x no histórico do grupo.
3. **Triagem de `ignored_messages`**: varrimento periódico da tab
   "🚫 Ignoradas" a assinalar candidatos suspeitos (possíveis falsos
   negativos de gestão que o classificador ignorou) para revisão humana —
   nunca reclassifica sozinho.
4. **Resumo semanal em linguagem natural**: usa os números já calculados
   pelo relatório semanal (Item 11 — PF/DD/uptime/rollbacks) e escreve um
   resumo legível em português para o Telegram. O cálculo continua
   determinístico; o LLM só redige o texto.

**Fora de âmbito, explicitamente**: o LLM não decide abrir/fechar trades,
não muda parâmetros de risco, não aprova promoções de fase (Fase 2→3, real)
e não decide sozinho se um resultado de sweep é aceitável — essas decisões
continuam a usar os gates numéricos fixos já definidos (curva monotónica,
N≥20, etc.), nunca automatizados por um modelo.

**Critério de aceitação**:
- Cada um dos 4 papéis corre em modo "sugestão/alerta", nunca em modo
  "ação automática" — auditável (cada sugestão fica registada com o
  contexto que a gerou).
- Reutiliza a configuração `SIGNALBOT_LLM_*` já existente; sem novo custo se
  a chave não estiver definida (todos os papéis ficam inativos por defeito,
  tal como o fallback de parsing).
- Testado manualmente pelo menos um exemplo de cada papel antes de agendar
  como corrida periódica.
